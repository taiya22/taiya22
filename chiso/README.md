# 地相（CHISO）

> その土地の地形は、どんな産業を養えるのか。そして今、そこで何が詰まっているのか。

公開されている地形・制度・産業・静脈データを重ね、地域単位で「地形が養える産業」と
「今そこで詰まっているもの」を、**層を分けたまま**並べて見せる分析基盤。

**まず [`CHISO.md`](CHISO.md) を読むこと。** 目的・要件・作業指針のすべてがそこにある。

---

## 4つの原則（変更不可）

1. **三層を混ぜない** — 全指標は `ESTIMATE`（地形からの推定）/ `ACTUAL`（実在の証拠）/
   `LEGAL`（法規制）/ `FIELD`（現地観測, v0.2）のいずれかに属す。異なる層の値を掛け合わせて
   単一の数値を作らない。
2. **合成した総合スコアを持たない** — 軸ごとに素の値を保持。重み付けはビューアUIのみで、
   結果はデータに保存しない。
3. **すべての指標に `limitations` を持たせる** — 「何が分からないか」を必ず併記する。
4. **断定を出力しない** — 「有望」「買うべき」「安全」等の語を出力に使わない。

このツールは推奨も断定もしない。出すのは指標値と、その根拠と、限界だけ。
足を運ぶ先を自分で選ぶための道具であって、精度を競うモデルではない。

## クイックスタート

```bash
# 依存インストール（軽量セット）
pip install -e .

# 合成デモ県で、データ生成〜出力までを一本で実行（ネットワーク不要・完全に決定論的）
chiso run --pref demo

# 地図で見る（ローカルHTTPサーバが立ち上がる）
chiso serve --pref demo
#  → http://localhost:8765/
```

`demo`（デモ県）は**合成・架空**のデータで、実在の土地を一切表しません。
外部データに到達できない環境でもパイプライン全体を再現・検証できるように用意した、
決定論的な「架空の土地」です。出力・ビューアには常に `SYNTHETIC` を明示します。

### 実在の県で動かす（ネットワークが必要）

```bash
chiso run --pref nagano   # 長野 / oita 大分 / yamagata 山形
```

`fetch` は国土地理院（GSI）の標高タイル（公開・ログイン不要）を取得します。
実県の補助レイヤー（河川・温泉・法規制ポリゴン・統計）の取り込みは v0.2 の範囲で、
現状は地形由来の `ESTIMATE` のみを評価します（`data/SOURCES.md` に取得を記録）。

## コマンド

| コマンド | 対応 | 内容 |
|---|---|---|
| `chiso fetch --pref <k>` | F-01 | データ取得（実データ or 合成デモ）→ `data/raw/` |
| `chiso terrain --pref <k>` | F-02 | DEM→傾斜/斜面方位/起伏/谷底/集水を1kmメッシュに集約 |
| `chiso assess --pref <k>` | F-03 | `rules/*.yaml` を層別に評価（合成しない） |
| `chiso stagnation --pref <k>` | F-04 | 市区町村単位の詰まり指標を並置 |
| `chiso export --pref <k>` | F-05 | GeoJSON + CSV + meta（layer と limitations を含む） |
| `chiso serve --pref <k>` | F-06 | ビューアに配置してローカルで地図表示 |
| `chiso run --pref <k>` | — | 上記を一本で実行（受け入れ基準6） |

対象6業種：温泉宿 / 発酵（酒・味噌・醤油）/ 林業・木工 / 果樹 / 水産加工 / 山岳観光・トレイル。

## 設計上の判断（実装メモ）

- **依存は軽量セット**（numpy / pandas / pyarrow / requests / pyyaml / click）。
  CHISO.md §6 が挙げる geopandas/rasterio/richdem/duckdb は、可搬性・再現性を優先して
  必須依存から外し、地形演算は numpy、GeoJSON は自前書き出しで実装している
  （`geo` extras で任意に追加可能）。
- **規則とコードの分離**：適性規則は `rules/*.yaml`。人が書き、直すのにコードを触らない。
  各条件は機械可読な `check` と、人間可読な `description`・必須の `limitations` を持つ。
- **説明可能性**：機械学習は使わない。すべての判定は規則からの演繹で、
  どの入力・どの条件から導かれたかをメッシュ単位で追跡できる（ビューアのクリックで層別表示）。
- **ビューアは自己完結**：MapLibre GL JS を `viewer/vendor/` に同梱し、外部CDN・タイルに
  依存しない。合成デモを実地図の上に重ねて誤認させないため、既定では背景地図を敷かない。

## ディレクトリ

```
chiso/
├── CHISO.md / CLAUDE.md    目的・要件・作業指針（最初に読む）
├── rules/                  産業適性ルール（YAML、人が書く）
├── src/chiso/              cli / fetch / terrain / assess / stagnation / export
├── data/SOURCES.md         出典・ライセンス台帳（fetch が追記）
├── field/                  現地記録（v0.2）
├── output/                 成果物（.gitignore）
├── viewer/                 自己完結の静的HTMLビューア
└── tests/
```

## テスト

```bash
pip install -e ".[dev]"
pytest -q
```

原則の作り込み（層の純度・断定語の不在・limitations 必須・決定性・非合成）を機械的に検証している。
