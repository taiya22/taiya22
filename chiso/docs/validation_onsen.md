# 温泉宿ルールの照合ノート — 長野（湯田中・渋）／箱根／有馬

CHISO.md 第II部 §10・第III部「作りながら歩く」に沿った、**既知の温泉地と規則の照合**。
温泉宿ルール（`rules/onsen_ryokan.yaml`）が、地形の異なる3つの実在温泉地で
何を捉え、何を取りこぼすかを事前に読み、規則を直す。

> 注意: 本ノートは **規則の事前レビュー（予測）** であって、測定結果ではない。
> 実際の傾斜・起伏・谷底などの数値は、GSI DEM に到達できる環境で
> `chiso run --pref hakone`（/ `yudanaka` / `arima`）を実行して得る。
> 本リポジトリの実行環境は GSI へのネットワークが遮断されているため、
> **ここで実データ地図は生成していない**（合成データに実在地名を付けることは、
> 「推定を事実と誤解させない」原則に反するため行わない）。

対象と実座標（`src/chiso/config.py`）:

| key | 地域 | 概略bbox | 地質（成因） |
|---|---|---|---|
| `yudanaka` | 湯田中・渋温泉郷（長野県山ノ内町） | 36.70–36.80N, 138.38–138.49E | 志賀火山群（第四紀火山）／**火山性** |
| `hakone` | 箱根温泉郷（神奈川県箱根町） | 35.17–35.29N, 138.98–139.14E | 箱根火山（活火山・カルデラ）／**火山性** |
| `arima` | 有馬温泉（兵庫県神戸市北区） | 34.76–34.83N, 135.21–135.29E | 六甲花崗岩／**非火山性（有馬型）** |

温泉宿ルールの推定層（ESTIMATE）の条件（重み）:
`volcanic_geology`(高) / `valley_position`(中) / `relief_context`(中) /
`buildable_flat`(中) / `water_access`(低)。
現況層（ACTUAL）: 温泉の近接・宿泊業の実在。法的層（LEGAL）: 土砂災害警戒区域・自然公園。

---

## 1. 湯田中・渋温泉郷（長野）— 火山性・谷あい

- **地質**: 志賀高原・横手山など第四紀火山帯のふもと → `volcanic_geology` は該当（高重み点灯）。
- **地形の予測**: 夜間瀬川の**谷底・扇状地**に温泉街、周囲は志賀の大起伏。
  → `valley_position`・`relief_context`・`buildable_flat` が谷筋で揃いやすい。
- **予測されるESTIMATE**: 谷筋で高い。温泉街の位置と概ね重なるはず。
- **ACTUAL**: 湯田中・渋・上林の各温泉が実在（点＋宿泊業）。
- **読み**: ESTIMATE と ACTUAL が**重なる**素直なケース。規則の想定どおり。

## 2. 箱根温泉郷 — 火山性・カルデラ

- **地質**: 箱根火山（活火山）。カルデラ内外に温泉 → `volcanic_geology` 該当（点灯）。
- **地形の予測**: 箱根湯本（早川の谷・低所）は `valley_position`＋`buildable_flat` が成立。
  一方、強羅・仙石原・芦之湖畔は**斜面・カルデラ床**で、平坦地条件の出方が場所により割れる。
- **予測されるESTIMATE**: 谷底の湯本で高く、山腹の強羅などでは `buildable_flat` が弱含み
  → **温泉街スケールで濃淡が出る**。行きたい場所を絞るのに使える差。
- **ACTUAL**: 湯本・強羅・仙石原・芦之湯が実在。
- **LEGAL（本実行では未投入）**: 実際には富士箱根伊豆国立公園・土砂災害警戒区域が広く関わる。
  → ローカルで国土数値情報を入れると LEGAL が濃く出る想定（v0.2）。
- **読み**: ESTIMATE の**空間的濃淡**が最も情報を持つケース。合成点にせず、素の濃淡で見る意義が出る。

## 3. 有馬温泉 — **非火山性（有馬型）**：規則の急所

- **地質**: 六甲山地の花崗岩体。近傍に第四紀火山なし。湧出は**深部流体（有馬型）**由来で
  **非火山性** → `volcanic_geology` は**該当しない（高重みが点灯しない）**。
- **地形の予測**: 六甲の急峻な谷あいに温泉街。`relief_context` は高いが、
  `valley_position`・`buildable_flat` は狭隘で場所により弱い。
- **予測されるESTIMATE**: **低め**。火山地質という最重視の手がかりが欠けるため、
  地形からは「温泉宿の素地」と読みにくい。
- **ACTUAL**: 有馬温泉は日本有数の温泉地として**明確に実在**。
- **読み — ここが核心**:
  有馬では **ESTIMATE（低）と ACTUAL（高）が食い違う**。
  総合スコアを持つ設計なら、この食い違いは平均で打ち消され「中程度」と誤って要約される。
  本システムは**層を分けたまま**なので、
  「地形推定は低い／だが温泉は実在する」という**差分がそのまま見える**。
  この差分こそ、地形だけでは説明できない温泉（有馬型・化石海水・断層沿い湧出）の
  存在を示す信号であり、歩いて確かめるべき対象になる。
  **規則が“外した”ことが、そのまま価値ある発見になる。**

---

## 照合から規則へ反映したこと

1. `rules/onsen_ryokan.yaml` の業種 `limitations` に、**非火山性温泉は推定層では
   説明できない**旨と、有馬を代表例として明記した（ESTIMATE が低くても ACTUAL が
   成立しうること、両者の差を合成して打ち消さないことを含む）。
2. **やらないと決めたこと**: 有馬の食い違いを“直す”ために ACTUAL の重みを上げて
   ESTIMATE と混ぜること。これは原則1（層を混ぜない）違反であり、
   規則が外したという事実を隠すことになる。**差分は残すのが正しい。**

## 将来の規則拡張（v0.2、データが要る）

- 非火山性温泉を地形側から補足する候補として、**活断層・地質境界の近接**を
  ESTIMATE の別条件に加える案（産総研 活断層データ／地質境界）。ただし
  「火山性の代替」ではなく**独立した弱いシグナル**として足す。合成はしない。
- LEGAL の実投入（国土数値情報：自然公園・保安林・土砂災害警戒区域）。
  箱根・湯田中は国立/国定公園の規制が濃く関わるため、ローカルでの取り込み効果が大きい。

## ローカルでの再現手順（GSI 到達環境）

```bash
pip install -e .
chiso run --pref hakone     # / yudanaka / arima
chiso serve --pref hakone   # 温泉宿を選び、推定層と現況層の重なり・食い違いを見る
```

`fetch` は GSI 標高タイル（公開・ログイン不要）を取得し、
`known.py` が**地質分類（火山性か否か）と温泉の存在のみ**を引用付きで手動投入する
（地形は DEM から算出、法規制・河川・統計は未投入）。有馬では推定層が低く出るのが
正しい挙動であり、それが現況層との差として地図に残る。
