## 1. プロジェクト概要

| 項目 | 内容 |
|------|------|
| サービス名 | 天気服装（Tenki Fukusou） |
| コンセプト | ゼロ入力で、一日中快適に過ごせるコーディネートを即提案 |
| 形態 | スマホ対応 静的Webアプリケーション（HTML/CSS/JS） |
| デプロイ | GitHub Pages |
| データ保存 | LocalStorage（クライアントサイド完結） |

### コアバリュー

> **「開くだけで、今日一日の服が決まる。」**

アプリを起動した瞬間に、朝の出発から夜の帰宅まで気温変化・天気変化に対応できるコーディネートを自動提案する。ユーザーの入力は不要。位置情報と登録済みワードローブから、最適な一日の服装プランを生成する。

---

## 2. 目的・背景

### 解決する課題

- 毎朝「何を着ていこう」と悩む時間の無駄
- 朝は寒かったのに昼は暑い、夜はまた冷える ── 一日の気温差への対応が難しい
- 天気予報は見るが、それを服装に変換する判断が面倒
- 午後から雨なのに傘を忘れる、上着を持っていかない

### 提供する価値

- **ゼロ入力**: アプリを開くだけで今日のコーデが表示される
- **一日全体カバー**: 朝〜夜の気温変化を考慮したレイヤリング提案
- **天気変化対応**: 途中からの雨・風にも備えたアイテム提案
- **パーソナライズ**: 自分の手持ち服から提案されるので実用的

## 4. 機能要件

### FR-01: 自動天気取得

| 項目 | 仕様 |
|------|------|
| 位置情報 | Geolocation API で自動取得（初回のみ許可ダイアログ） |
| フォールバック | 保存済み都市名を使用（デフォルト: 東京） |
| 天気データ | 今日の時間帯別（朝6-9時 / 昼9-15時 / 夕15-18時 / 夜18-23時）の気温・天気・降水確率・風速 |
| データソース | モックデータをデフォルト搭載。設定画面でOpenWeatherMap APIキーを入力すると実データに切替 |
| 更新頻度 | アプリ起動時に自動取得。手動リフレッシュボタンあり |

### FR-02: 一日コーディネート提案（コア機能）

| 項目 | 仕様 |
|------|------|
| 提案形式 | 一日を通して対応できる服装セットを1画面で表示 |
| 構成要素 | ベースレイヤー（インナー）+ ミドルレイヤー + アウター + ボトムス + 靴 + 小物 |
| レイヤリング | 一日の最高・最低気温差に応じて「脱ぎ着できる」組み合わせを提案 |
| 天気対応 | 雨予報 → 撥水アウター or 傘を追加、強風 → 防風アウター推奨 |
| 持ち物提案 | 脱いだアウターを持ち歩く想定、折り畳み傘、サングラス、日焼け止め等 |
| 代替提案 | 「別のコーデを見る」ボタンで別の組み合わせを表示 |
| 一日の流れ表示 | 「朝: ジャケットを羽織る → 昼: 脱いで腕まくり → 夜: 再び羽織る」のタイムライン |

### FR-03: ワードローブ管理

| 項目 | 仕様 |
|------|------|
| 操作 | 追加 / 編集 / 削除（CRUD） |
| カテゴリ | トップス / ボトムス / アウター / 靴 / 小物（傘・帽子・マフラー等） |
| 登録項目 | 名前、カテゴリ、サブカテゴリ、色、暖かさレベル（1-5）、天気適性（晴/雨/雪/全天候）、画像（任意） |
| サブカテゴリ例 | トップス → Tシャツ / シャツ / ニット / パーカー / カーディガン |
| 初期データ | サンプルワードローブをプリセット（デモ体験用） |
| データ保存 | LocalStorage |

### FR-04: お気に入り・履歴

| 項目 | 仕様 |
|------|------|
| お気に入り | 気に入ったコーデを保存。後日再提案可能 |
| 履歴 | 過去7日分の提案コーデを自動記録 |
| 重複回避 | 直近3日と同じコーデは避ける |

### FR-05: パーソナル設定

| 項目 | 仕様 |
|------|------|
| 体感温度調整 | 暑がり（+2℃補正）/ 普通 / 寒がり（-2℃補正） |
| 都市設定 | 手動で都市名を設定（位置情報の代替） |
| APIキー | OpenWeatherMap APIキー入力欄（任意） |
| データ管理 | ワードローブのエクスポート / インポート（JSON） |

## 5. 非機能要件

| 項目 | 要件 |
|------|------|
| レスポンシブ | モバイルファースト。375px〜対応 |
| パフォーマンス | 初回表示 2秒以内（モックデータ時） |
| オフライン | 最後に取得した天気データをキャッシュ。オフラインでも前回データで提案可能 |
| アクセシビリティ | セマンティックHTML、十分なカラーコントラスト比 |
| ブラウザ対応 | iOS Safari 15+、Android Chrome 90+、デスクトップ主要ブラウザ |
| セキュリティ | APIキーはLocalStorageに保存（クライアントサイドのみ使用） |
| サーバー | 不要。完全静的サイト |

## 8. レコメンドロジック

### 8.1 気温帯ルール（6段階）

| レベル | 気温範囲 | ベースレイヤー | ミドルレイヤー | アウター |
|--------|----------|---------------|---------------|---------|
| 極寒 | 〜5℃ | knit / hoodie | cardigan / fleece | coat / down |
| 寒い | 5〜10℃ | knit / shirt+knit | cardigan | jacket / coat |
| やや寒い | 10〜15℃ | shirt / knit | なし or cardigan | jacket |
| 快適 | 15〜22℃ | shirt / 薄手knit | なし | なし or light jacket |
| やや暑い | 22〜28℃ | tshirt / shirt | なし | なし |
| 暑い | 28℃〜 | tshirt / tank | なし | なし |

### 8.2 一日レイヤリングロジック

```
一日の気温差 = 最高気温 - 最低気温

IF 気温差 >= 10℃:
  → 最低気温に合わせたアウター + 最高気温に合わせたベース
  → タイムライン: 「朝は羽織る → 昼は脱ぐ → 夜はまた羽織る」
  → 持ち物: 脱いだアウターを持ち歩く想定

IF 気温差 >= 5℃ かつ < 10℃:
  → 最低気温基準でやや軽めのアウター + 快適ベース
  → タイムライン: 「朝は羽織っても昼には不要かも」

IF 気温差 < 5℃:
  → 平均気温に合わせた一定の服装でOK
  → タイムラインなし（一日同じ服装で快適）
```

### 8.3 天気対応ルール

| 天気条件 | 対応 |
|----------|------|
| 降水確率 50%以上（いずれかの時間帯） | 傘を持ち物に追加。撥水素材アウター優先 |
| 降水確率 30-50% | 折り畳み傘を持ち物に追加 |
| 雪 | 防水靴優先。ダウン/コート必須 |
| 強風（風速 10m/s以上） | 防風アウター優先。帽子注意 |
| 晴れ + 気温25℃以上 | サングラス・帽子を持ち物に追加 |
| UV指数高 | 日焼け止めを持ち物に追加 |

### 8.4 体感温度補正

```
実効気温 = 実際の気温 + 体感補正値

暑がり: 補正 = +2℃（実際より暑く感じる → 薄着寄りに）
普通:   補正 =  0℃
寒がり: 補正 = -2℃（実際より寒く感じる → 厚着寄りに）
```

### 8.5 ワードローブマッチング

```
1. 気温帯ルールから必要なカテゴリ・サブカテゴリを決定
2. ユーザーのワードローブから該当する服をフィルタリング
3. 天気適性でさらに絞り込み
4. 直近3日の履歴と重複しないものを優先
5. お気に入りアイテムに軽い加点
6. ランダム要素を加えて最終選定
```

## 10. UI/デザイン方針

### カラーパレット（独自デザイン）

| 名前 | Hex | 用途 |
|------|-----|------|
| Sky Blue | `#4A90D9` | プライマリー（ヘッダー、ボタン） |
| Warm Orange | `#F5A623` | アクセント（CTA、ハイライト） |
| Soft White | `#F8F9FA` | 背景 |
| Dark Gray | `#2D3436` | テキスト |
| Light Gray | `#DFE6E9` | ボーダー、区切り |
| Success Green | `#00B894` | 成功状態、快適気温 |
| Alert Red | `#E17055` | 警告（極端な気温、雨） |

### タイポグラフィ

| 要素 | フォント | サイズ |
|------|---------|--------|
| 見出し | Noto Sans JP 700 | 20-24px |
| 本文 | Noto Sans JP 400 | 14-16px |
| ラベル | Noto Sans JP 500 | 12-13px |
| 数値（気温） | system-ui 700 | 28-36px |

### デザイン原則

- 角丸を多用（border-radius: 12-16px）し、親しみやすさを演出
- カード型UIでコンテンツを区切る
- 天気に合わせたグラデーション背景（晴れ → 青、曇り → グレー、雨 → 濃いグレー）
- アイコンは絵文字を活用（外部ライブラリ不要）
- アニメーションは軽微に（0.3s ease トランジション）
